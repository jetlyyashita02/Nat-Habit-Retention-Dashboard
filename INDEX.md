# GitHub Index — Retention & Category Intelligence Dashboard

File manifest for the repository. This project is a **clean build** (no pre-existing
dashboard was uploaded), so every file below is **NEW** — add them all in one commit.

## The deliverables

1. **The 10-page interactive dashboard site** (the final deliverable) — ten real, separate,
   openable HTML pages at the repo root (`index.html` → overview, `migration.html`,
   `sales.html`, `nps-cs.html`, `pricing.html`, `retention.html`, `ntc.html`,
   `definitions.html`, `insights.html`, plus `journey.html`, the retention deep-dive).
   Each page is self-contained (zero external references, works offline / GitHub Pages)
   and genuinely interactive: hover tooltips with crosshair on every chart, click-to-drill
   bars/heat rows, sortable + searchable tables, cross-filters (NPS category bar →
   Voice-of-Customer panel; top price mover → Source-B table), an "⚡ Deep cuts"
   section on every page with auto-detected conclusions, and a **📂 Live data panel on
   every page**: drop in your own CSVs (upload or paste) and the page re-computes its
   analysis **in your browser** with the same rules as the bundled pipeline (robust
   header detection, warnings not crashes, generic structural profile for unmatched
   files, one-click reset to bundled data). Tested headlessly by `tests/web_harness.js`
   (113 checks, incl. [11] live recompute vs the embedded Python-pipeline values).
   **Generated, never hand-edited** — one command: `python make_web_dashboard.py`
   (self-verifies every page; re-runs the journey deep-dive only when stale).
   Also kept: `single-page.html` — the legacy single-file 9-tab version
   (`python make_static_dashboard.py`).
2. **`journey.html` — the retention deep-dive** (single self-contained file: the full
   per-customer journey embedded — 152,091 customers · 193,756 orders — with live clickable
   filters, auto-detected insights, retention curves with the N/A maturity rule, V2V/V2C,
   seasonality, geography × season, switching behaviour, and a paginated Journey explorer with
   CSV export; zero external references). Regenerated by `make_retention_dashboard.py`;
   tested headlessly by `tests/retention_harness.js`.
3. **The Streamlit app** (`app.py` + `pages/`) — the upload-driven engine that recomputes
   everything from fresh CSVs. Upload the new month's 7 CSVs, re-run
   `python make_web_dashboard.py`, and commit the generated HTML files.

## Deploying the dashboard on GitHub Pages

1. Push the repo (see data notes below first — the samples contain real business data).
2. GitHub → **Settings → Pages → Build and deployment → Source: `main` branch, `/` (root)**.
3. Done — `https://<your-username>.github.io/<repo>/` serves `index.html` directly.
   The file has no external references, so it works offline, in iframes and on Pages.

To update next month: upload the new CSVs in the app → `python make_web_dashboard.py`
→ commit the 10 HTML pages → Pages deploys automatically.

## Data notes (read before pushing)

1. **`data/sample_journey_d2c.csv` is ~25 MB** — if the repo has a per-file size limit or
   you prefer, add it to Git LFS:
   `git lfs track "data/*.csv"` (or track only that file) — or commit the repo without it
   and document that the page auto-degrades with an "upload required" state.
2. The `data/` samples **and the generated HTML pages contain real business
   numbers** (revenue, NPS, migration counts). If the data is confidential, either **keep the
   repo private** or replace the samples with redacted extracts and regenerate the pages from
   the redacted samples — the parsers accept column renames, so redaction is safe.
3. `uploads/` holds the untouched source files; it is gitignored by design.
